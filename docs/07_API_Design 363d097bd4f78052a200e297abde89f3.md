# **3. 認証API**

# **3-1. ログイン**

## **Endpoint**

```
POST /api/v1/auth/login
```

---

## **説明**

メールアドレスとパスワードでログインを行う。

---

## **Request**

```json
{
  "email": "test@example.com",
  "password": "password123"
}
```

---

## **Response**

```json
{
  "success": true,
  "data": {
    "accessToken": "jwt-access-token",
    "refreshToken": "jwt-refresh-token",
    "role": "USER"
  }
}
```

---

## **異常系**

| **Code** | **内容** |
| --- | --- |
| AUTH-001 | 認証失敗 |
| AUTH-002 | 停止アカウント |

---

# **3-2. Refresh Token再発行**

## **Endpoint**

```
POST /api/v1/auth/refresh
```

---

## **Request**

```json
{
  "refreshToken": "jwt-refresh-token"
}
```

---

## **Response**

```json
{
  "success": true,
  "data": {
    "accessToken": "new-access-token",
    "refreshToken": "new-refresh-token"
  }
}
```

> **注記:** Refresh Token Rotation方式を採用。再発行時に旧Tokenを失効させ、新しいAccess Token・Refresh Tokenを両方返却する。
> 

---

## **異常系**

| **Code** | **内容** |
| --- | --- |
| AUTH-003 | 無効なRefresh Token |
| AUTH-004 | 期限切れのRefresh Token |
| AUTH-002 | 停止アカウント |

# **8-5. 予約枠BLOCKED設定**

## **Endpoint**

```
PATCH /api/v1/admin/hospitals/{hospitalId}/schedules/{scheduleId}/block
```

## **説明**

指定した予約枠を`BLOCKED`（予約不可）に変更する。臨時休診・担当医不在等、病院側の都合で枠を閉じる場合に使用する。

**予約が入っているかどうかは判定しない。** 重複予約防止は`reservations`側の制約（`06_ERD` §12・§18参照）であり、本APIは`hospital_schedules.status`のみを変更する。

## **権限**

| **Role** |
| --- |
| ROLE_HOSPITAL_ADMIN |
| ROLE_SYSTEM_ADMIN |

## **Response**

```json
{
  "success": true,
  "data": null
}
```

## **異常系**

| **Code** | **内容** |
| --- | --- |
| HOSPITAL-002 | 存在しない予約枠、または指定した`hospitalId`に属さない予約枠 |

---
