# **1. ERD概要**

本ドキュメントでは、「大ペット」における主要テーブル、リレーション、制約、論理名、物理名を定義する。

本システムでは、ユーザー、認証トークン、ペット、病院、病院営業時間、予約可能時間、予約、健康記録、ワクチン接種予定、通知情報を管理する。

# **9-1. hospital_business_hours**

## **概要**

病院の曜日別デフォルト営業時間を管理する。バッチ（Scheduler）がこのテーブルを参照し、`hospital_schedules`へ一定期間分（例: 1ヶ月）の予約枠を自動生成する。

| **論理名** | **物理名** | **Type** | **PK** | **FK** | **Null** | **Unique** | **Default** | **説明** |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 営業時間ID | id | BIGINT | ○ |  | NO | ○ | GENERATED BY DEFAULT AS IDENTITY | 営業時間識別子 |
| 病院ID | hospital_id | BIGINT |  | ○ | NO |  |  | hospitals.id |
| 曜日 | day_of_week | VARCHAR(10) |  |  | NO |  |  | MONDAY〜SUNDAY（`java.time.DayOfWeek`のname()と一致させる） |
| 営業開始時刻 | open_time | TIME |  |  | NO |  |  | 営業開始時刻 |
| 営業終了時刻 | close_time | TIME |  |  | NO |  |  | 営業終了時刻 |
| 休憩開始時刻 | break_start_time | TIME |  |  | YES |  | NULL | 休憩（昼休み等）開始時刻。休憩なしの場合はNULL |
| 休憩終了時刻 | break_end_time | TIME |  |  | YES |  | NULL | 休憩終了時刻 |
| 予約枠単位（分） | slot_duration_minutes | INT |  |  | NO |  | 30 | 1予約枠あたりの時間（分） |
| 作成日時 | created_at | TIMESTAMP |  |  | NO |  | CURRENT_TIMESTAMP | 作成日時 |
| 更新日時 | updated_at | TIMESTAMP |  |  | NO |  | CURRENT_TIMESTAMP | 更新日時 |

### **制約**

| **制約** | **内容** |
| --- | --- |
| UNIQUE | hospital_id, day_of_week |

### **業務ルール**

- 特定の曜日にレコードが存在しない場合、その曜日は休診として扱う（「休診フラグ」は持たない）。
- 論理削除（`deleted_at`）は持たない。運用設定データであり、`hospital_schedules`と同様に履歴保持の対象外とする。

# **18. 設計上の考慮事項**

## **Refresh Token管理**

Refresh TokenはDBで管理する。

ログアウト、Token再発行、Token失効制御を可能にするためである。

## **予約枠管理**

病院の予約可能時間は`hospital_schedules`で管理する。

これにより、病院ごとの休診日、予約不可時間、予約枠単位の制御が可能になる。

---

## **病院営業時間と予約枠自動生成**

病院ごとの営業時間は、日付単位ではなく`hospital_business_hours`で**曜日単位**で管理する。日付単位で個別登録する方式に比べ、登録の手間が少なく、通常運用（毎週同じ曜日は同じ営業時間）に合致する。

予約枠（`hospital_schedules`）はこの曜日別営業時間を元に、Scheduler（バッチ）が一定期間分（例: 翌月分）を先読みして自動生成する（`04_System_Architecture` §14 Scheduler構成 参照）。生成ロジックの方針:

- `open_time`〜`break_start_time`、`break_end_time`〜`close_time`の各区間を`slot_duration_minutes`単位で分割し、それぞれ`AVAILABLE`の`hospital_schedules`行を生成する。
- `break_start_time`〜`break_end_time`（休憩・昼休み）の区間も同じ単位で分割し、`BLOCKED`の行として生成する（行自体を作らず「空白」にする方式ではなく、明示的にBLOCKED行を作ることで、画面上「休憩中」であることを表示できるようにする）。
- 同一病院・同一曜日のレコードが`hospital_business_hours`に無い場合、その曜日は予約枠を生成しない（休診扱い）。
- 手動で`hospital_schedules`を`BLOCKED`にした枠（臨時休診等）は、バッチの再実行で上書きしない（生成済みの期間は再生成しないか、既存レコードをスキップする）。

**予約による自動BLOCKEDは行わない。** `hospital_schedules.status`は病院側の都合による提供可否のみを表し、「その枠がすでに予約で埋まっているか」は`reservations`側で`schedule_id`に対するREQUESTED/APPROVED件数を確認して判定する（§12 業務制約 参照）。この2つを分けることで、予約キャンセル時に`hospital_schedules`側の状態を戻す同期処理が不要になる。

---

## **重複予約防止**

同一`schedule_id`に対して、`REQUESTED`または`APPROVED`状態の予約は1件のみ許可する。`REJECTED`、`CANCELLED`、`COMPLETED`は履歴として保持する。

---

## **論理削除**

予約、健康記録、ワクチン情報は履歴性が高いため、物理削除ではなく論理削除を基本とする。

---

## **通知設計**

通知は予約またはワクチンに関連する可能性があるため、`reservation_id`、`vaccination_id`はnullableとする.
