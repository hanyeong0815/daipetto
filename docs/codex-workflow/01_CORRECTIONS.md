## 論理・運用上の訂正

| 原文の主張 | 問題 | 訂正版 |
|---|---|---|
| レビュー担当には diff だけを見せる。一方で仕様・テスト記録も渡す | 入力範囲が矛盾する | 要求・受け入れ条件・diff・関連コード・検証記録を渡す。実装者の長い会話や結論を初回評価の前提にしない |
| 別ベンダーなら真に独立した検証になる | 同じ仕様誤解・誤ったテストを共有し得る | 独立性を高める手段。正しさは再現手順、テスト、コードの根拠で判断する |
| Claude は設計に強く、Codex はアーキテクチャ監修に固定する | 能力比較から役割を一意に導けない | ユーザーの選好として Claude 主実装・Codex 主レビューを採用。依頼と実績に応じて交代可能 |
| 実装は必ず新しいセッションで行う | 工程分離とセッション分離を混同 | 計画と実装の工程を分ける。長大な会話・方針転換時は新規セッションを選び、確定仕様を引き継ぐ。公式の工程説明も毎回の新規セッションを必須化していない [S4] |

| CodeRabbit 等で一貫性を保証する | レビュー支援は規則の強制や正しさの保証ではない | 必須条件はテスト・静的検査・CI に置く。追加サービスは任意 |
| サンドボックスの自律実行なら操作は自由 | 実行能力と許可を混同 | 実際の権限・ネットワーク制約と依頼範囲に従う |

## 製品情報の扱い

- **確認済み**: GPT-6 Astra は公式モデルページに掲載されている。モデル名と Codex / ChatGPT という製品・実行環境を区別する。[S1]
- **料金表現を訂正**: Astra の通常 API 料金は100万トークン当たり入力 $10、出力 $50。272K 入力超では全リクエストの入力・キャッシュ料金が2倍、出力料金が1.5倍であり、「すべて2倍」は不正確。API の料金とサブスクリプションの使用枠は別に扱う。[S1]
- **固定保証から参考値へ訂正**: 公式表にも Plus の Astra ローカルメッセージは5時間当たり5〜45とあるが、作業量・速度設定などで消費が変わる。固定回数の保証として計画せず、利用時の公式表とアカウント表示を確認する。[S2]
- **Claude の既定モデルと利用権を区別**: 公式設定資料は Pro / Team Standard の既定を Sonnet 5 としている。「既定が Sonnet」から「Opus は利用不可」を導かない。長文コンテキストや追加使用にはプラン条件がある。[S5]
- **保留**: 原文の各モデルの公開日、全ラインアップ、モデル廃止の一括表現、ベンチマーク数値、自己欠陥見落とし率、一般チャットでの提供範囲、Claude の全料金・固定プロンプト数は、今回すべてを一次資料で照合していない。運用規則の根拠には採用しない。
- **比較の限界**: 異なる harness、推論量、モデル版、評価時点のスコアから実プロジェクトの優劣は確定できない。「SWE-bench の発表値なし」と「システムカードに値あり」は資料と版を分ければ両立し得るが、原文の二次情報だけでは確定しない。
- **認証・課金**: API キー、サブスクリプション、外部プロバイダーの認証経路を実行前に確認する。原文の環境変数に関する一般化だけで請求先を断定せず、キーの値をログや引き継ぎに載せない。
